# Критерии приёмки объединённого продукта

| ID | Критерий | Как проверяется | Порог |
|---|---|---|---|
| **К1** | **Нет ручного обмена.** После подтверждения PO платёж регистрируется автоматически; в банковском интерфейсе нет полей ручного ввода суммы и хеша | AT-1 + замер времени (`registrationLatencyMs`), ревью UI (вкладка «Settlement» — поля только для чтения) | ≤ 10 000 мс |
| **К2** | **Согласованность состояний.** Статусы PO, платежа и хаба согласованы, сумма и хеш совпадают | скрипт сверки (`orchestrator/reconcile.ts`, функция `consistent`) после каждого из 30 прогонов и в конце приёмки | 0 расхождений |
| **К3** | **Защита общей операции.** Действия без полномочий, подмена суммы/хеша и повтор сообщения не меняют состояние | AT-2, AT-3, AT-5 + срабатывание R-1 / R-3 | все PASS, состояние неизменно |
| **К4** | **Восстановление после сбоя.** После отказа банка (пауза) или падения оркестратора незавершённые заказы доводятся до согласованного итога без дублей платежа | AT-4, AT-6 (время от восстановления до `Paid`, число платежей) | ≤ 60 000 мс, 1 платёж |

Фактические значения — в `docs/ACCEPTANCE_REPORT.md` и `reports/acceptance/`.
